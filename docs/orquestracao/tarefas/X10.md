# X10 — Bundle sem segredos

- **Dono:** Codex executor · **Revisão:** Claude · **Base:** `claude/ciclo-3` · **Faixa:** `scripts/check-bundle.mjs` (novo), `scripts/lib/bundle-scan.ts` + `scripts/lib/bundle-scan.test.ts` (novos), `docs/ENTREGA-CODEX.md`

## Objetivo

Um comando que, depois de `npm run build`, falha se a saída publicada (`.vercel/output/static`, `.vercel/output/functions`, e `.output` se existir) contiver material privilegiado.

## Abordagem

- Lógica pura em `scripts/lib/bundle-scan.ts` (recebe `{ path, content }[]`, devolve achados com arquivo e tipo, **sem** imprimir o valor encontrado); `scripts/check-bundle.mjs` só lê os arquivos e chama a lógica (padrão de `scripts/orq/codex-job.mjs` + `lib/`).
- Padrões: `sb_secret_…`, a string `service_role` dentro de um JWT decodificado (payload base64url com `"role":"service_role"`), `SUPABASE_SERVICE_ROLE_KEY` e chaves privadas PEM. A chave publicável (`sb_publishable_…`) e a URL do projeto são permitidas.
- Saída: lista de arquivos e tipo de achado; exit 1 se houver achado, 2 se a pasta de build não existir.

## Critérios de aceite

1. Testes cobrem: cada padrão detectado, publicável permitida, JWT com `role: anon`/`authenticated` permitido, valor nunca aparece na mensagem.
2. Rodado no build atual (mock e `VITE_DATA_SOURCE=supabase`): zero achados (registre a saída).
3. Sem dependências novas; não altere `package.json` (se quiser um script npm, registre em `out_of_scope_requests`).

## Testes

`npx vitest run scripts/lib/bundle-scan.test.ts`, `npx tsc --noEmit`, `npm run lint`, `npm run build && node scripts/check-bundle.mjs`.
