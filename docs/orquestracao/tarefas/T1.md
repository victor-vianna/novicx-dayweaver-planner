# T1 — Bloqueio de conta no banco

- **Dono:** Claude · **Revisão:** CXR ★ (`xhigh`) · **Depende:** E0 · **Faixa:** `supabase/migrations/20261025120000_blocked_accounts.sql`, `supabase/tests/03_blocked.test.sql` · **Depois:** AH push

## Objetivo

Conta bloqueada (`profiles.blocked_at` preenchido) perde **na hora** a leitura
de todas as tabelas, do Storage e o uso das RPCs, sem afetar outras contas.

## Abordagem

- `alter table profiles add column blocked_at timestamptz` (nulo = ativa).
- `is_admin()` exige `blocked_at is null`; `current_client_id()` junta `profiles` e exige `blocked_at is null`.
  Como todas as políticas de RLS (7 tabelas), as de `storage.objects` e as RPCs (`set_post_published`,
  `assign_plan`, `reorder_post_media`) dependem desses dois helpers, nenhuma política nova é necessária.
- Ninguém altera `blocked_at` pelo app: `profiles` continua sem política de UPDATE. Quem bloqueia é a
  Edge Function (T2, `service_role`) ou SQL do responsável. A própria conta bloqueada continua lendo
  só o próprio perfil (para a UI mostrar "acesso suspenso", T3).
- Sessões: o JWT já emitido continua válido até expirar, mas sem dados (helpers negam); T2 bane no Auth
  para invalidar o refresh.

## Riscos

- Helper esquecido fora de `is_admin`/`current_client_id` daria acesso a bloqueado → verificar que nenhuma política/RPC usa `auth.uid()` direto sem os helpers (exceção: `profiles_select`, intencional).
- Admin bloqueado ainda lê o próprio perfil (intencional).

## Critérios de aceite

1. Migration aditiva (coluna nova + `create or replace`), sem editar migration aplicada; helpers mantêm `security definer`, `stable`, `search_path = ''` e grants.
2. Cliente bloqueada: 0 linhas em `clients`, `client_packages`, `posts`, `post_media`, `storage.objects`; `set_post_published` recusa (`P0002`); `current_client_id()` nulo.
3. Cliente bloqueada não consegue se desbloquear (UPDATE em `profiles` afeta 0 linhas).
4. Outra cliente e admin ativo não são afetados; admin vê quem está bloqueado.
5. Admin bloqueado: `is_admin()` falso; não lê posts/planos/arquivos; não cria post, não contrata plano, não envia arquivo (`42501`).
6. `anon` continua sem acesso; desbloquear devolve o acesso.
7. pgTAP falha sem a migration e passa com ela (`--pending`), sem gravar nada.
