# X8 — Build para a Vercel

- **Dono:** Codex executor · **Revisão:** Claude · **Base:** `claude/ciclo-3` · **Faixa:** `vite.config.ts`, `vercel.json`, `docs/ENTREGA-CODEX.md`

## Contexto

`@lovable.dev/vite-tanstack-config` já inclui nitro (alvo **Cloudflare** por padrão), tanstackStart, React, Tailwind etc. — **não** adicione esses plugins de novo (ver comentário em `vite.config.ts`). O Lovable sincroniza pela `main` e precisa continuar funcionando.

## Objetivo

`npm run build` gerar saída para a Vercel (`.vercel/output`, preset `vercel` do nitro), SSR funcionando na raiz e 404.

## Abordagem sugerida

Passar o preset do nitro pela opção que o `defineConfig` do Lovable expõe (ou por variável de ambiente, ex.: `NITRO_PRESET=vercel`, se for o mecanismo suportado), escolhendo a forma que não quebre o build padrão do Lovable. Documente a escolha. Sem `vercel` CLI (não instalado): valide pela estrutura de `.vercel/output` (`config.json`, `functions/`, `static/`). Variáveis: só as três `VITE_*` (URL, chave publicável, data source).

## Critérios de aceite

1. `npm run build` (ou o comando documentado) gera `.vercel/output` com `config.json`, função SSR e estáticos.
2. Build mock e build com `VITE_DATA_SOURCE=supabase` passam.
3. Mudança mínima em `vite.config.ts`; se precisar de script em `package.json`, registre em `out_of_scope_requests`.
4. `docs/ENTREGA-CODEX.md` com os passos de deploy na Vercel (variáveis, comando, saída) e os riscos para o Lovable.

## Testes

`npm run build` (mock e supabase), `npx tsc --noEmit`, `npm run lint`.
