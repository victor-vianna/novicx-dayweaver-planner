# T6 — Status da publicação pelo banco, responsável, excluir só rascunho, CORS do download

- **Dono:** Claude · **Revisão:** CXR ★ (`xhigh`) · **Depende:** T5 · **Faixa:** `supabase/migrations/20261026100000_admin_post_status.sql`, `supabase/tests/06_post_status.test.sql` (+ `01_rls`: escrita direta de status vira `throws_ok`), `src/services/{posts.ts,mock/posts.ts,supabase/posts.ts,posts.test.ts}`, `src/services/supabase/flow.it.ts`, `src/lib/status.ts`, `src/features/admin/delivery/PostEditor{.tsx,.test.tsx}` · **Depois:** AH push

## Objetivo

"Publicado" só nasce de operação autorizada no banco, com data do servidor e responsável; a equipe não apaga histórico (só rascunho); o download da arte pelo navegador funciona a partir da origem do app.

## Abordagem

- `posts.published_by_user uuid → profiles` (nulo fora de `published`, por `check`).
- `admin_set_post_status(p_post_id, p_status)` (`security definer`, admin): trava o post; liberar (`≠ draft`) exige ≥1 arte (`P0001`); formato derivado da quantidade de artes; `published` → `now()`, `'admin'`, `auth.uid()`, mas post já publicado mantém o registro original; outros status limpam os campos. `anon`/`public` sem execução.
- `set_post_published` (mesma assinatura) passa a gravar/limpar `published_by_user`.
- Privilégio por coluna: `authenticated` só atualiza `title, caption, scheduled_date, scheduled_time, format`; `status`/`published_*` só pelas RPCs.
- Política de exclusão de posts: só admin e só `status = 'draft'`.
- Serviços: Supabase `updatePost` grava campos diretos e manda o status pela RPC; `deletePost` (novo, ambos os modos) recusa não rascunho e remove os arquivos depois da linha. Mock espelha as regras (arte obrigatória, formato, registro mantido, exclusão só de rascunho).
- Editor: botão "Excluir rascunho" com confirmação, só em rascunho.
- CORS: o E2E baixa a URL assinada com `Origin` do app e exige `access-control-allow-origin` `*` ou a origem (o Storage do Supabase não tem CORS configurável; é verificação, não mudança).

## Riscos

- `updatePost` com texto + status não é atômico (2 chamadas); o status (o que importa) é atômico com os campos de publicação e o formato.
- Remover a última arte de um post já liberado continua possível (`removePostMedia`); a RPC só valida na mudança de status.
- E2E remoto só roda depois do push (a escrita direta de status hoje ainda é aceita).

## Critérios de aceite

1. Migration nova, aditiva (único `drop` é o da política de exclusão de posts, recriada restrita); sem alteração de dados.
2. Cliente e anon → `42501` na RPC nova; admin e cliente não escrevem `status`/`published_*` direto (`42501`).
3. Liberar sem arte → `P0001`; formato derivado; publicar grava data, `admin` e perfil; republicar mantém o registro; voltar limpa.
4. Cliente publicando pela RPC dela grava o próprio perfil em `published_by_user`.
5. Excluir: rascunho sim; publicado não (admin e cliente).
6. pgTAP falha sem a migration e passa com `--pending`; `npm test`, tsc, lint e build verdes.
7. Depois do push: E2E remoto verde, incluindo CORS do download e recusa de exclusão/escrita direta.
