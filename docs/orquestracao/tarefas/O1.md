# O1 — `db:test:remote --pending`

## Objetivo

Testar migrations **ainda não aplicadas** no projeto dev sem gravá-las: elas
rodam dentro do mesmo lote revertido de cada arquivo pgTAP. Pré-requisito para
apresentar pushes (ORQUESTRACAO §5: "pgTAP `--pending` verde").

## Arquivos e travas

- `scripts/db-test-remote.mjs` — flag `--pending`; lista aplicada antes/depois.
- `scripts/lib/pending.ts` (+ `pending.test.ts`) — lógica pura.
- `scripts/lib/sql-guard.ts` (+ teste) — guarda "uma única transação" dos testes
  (correção I1 da revisão X4, já usada pelo runner; entra aqui porque o runner depende dela).

## Abordagem

1. Versões aplicadas: `select version from supabase_migrations.schema_migrations` via `supabase db query --linked`.
2. Pendentes = arquivos locais cuja versão não está aplicada; erro se alguma pendente for mais antiga que a última aplicada (fora de ordem).
3. Cada pendente passa por `assertEmbeddable` (sem `begin/commit/rollback/savepoint`, `concurrently`, `vacuum`, `alter system`, `create/drop database`; ignora corpos de função e strings).
4. `withPending` injeta as pendentes logo após o `begin;` do teste; o bloco final sempre lança exceção → tudo revertido (inclusive a migration).
5. Ao final, a lista aplicada é relida; se mudou, a execução falha.

## Riscos

- Migration com comando não transacional passaria despercebida → `assertEmbeddable` recusa antes de rodar.
- Migration pendente gravada por engano → impossível pelo desenho (lote aborta), e a comparação antes/depois detecta.
- Testes que conferem o conjunto exato de objetos (ex.: `tables_are`) falham legitimamente quando a pendente cria objetos novos — o autor da migration atualiza o teste.

## Critérios de aceite

1. Com `--pending`, migration pendente é executada dentro de cada lote (prova: teste-sonda `has_table` passa com `--pending` e falha sem).
2. Nada fica gravado: `supabase migration list --linked` idêntico antes/depois e o objeto criado pela sonda não existe depois (`to_regclass` nulo).
3. O runner falha se a lista aplicada mudar durante a execução.
4. Migration com controle de transação ou `concurrently` é recusada antes de rodar; palavras dentro de corpos de função/strings não disparam a recusa.
5. Pendente fora de ordem é recusada.
6. Sem `--pending`, o comportamento anterior é mantido (74/74).
